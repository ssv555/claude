---
name: Docs before testing
description: Always finalize documentation before testing — errors during testing can derail doc work
type: feedback
---

Always close documentation first, then test. If testing starts and errors appear, documentation gets forgotten.

**Why:** Testing can produce cascading errors that consume all attention — docs get deprioritized and forgotten.
**How to apply:** After completing a feature/setup, update docs and write migration notes BEFORE deploying or testing.
